Your assistant, inside every app you build.

The My Assistant API lets the apps you make use your assistant — the same one from My Assistant, with the same memory, voice and account. Your app can give it new powers it doesn't have in the main app, and everything it does there flows back, so My Assistant can tell you about it later.

One assistantSame personality, memory and recent conversation in every app.
New powersDeclare app tools — move a piece, start a timer — and the assistant uses them.
Voice to voiceOpen a realtime voice session from your app in one call.
Shared storyActivity and records your app saves are answerable from My Assistant.

Quickstart

1In My Assistant open Hub → Your own apps and tap Connect an app.
2Name it, choose what it may do, and copy the API key (shown once).
3Call the API from your app with that key.
4Ask My Assistant what happened there — it knows.

Every request goes to {{API}} with the key in the Authorization header. Say hello:

curl {{API}}/assistant/messages \
  -H "Authorization: Bearer $MYA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message": "Hi! What should I focus on today?"}'
const res = await fetch("{{API}}/assistant/messages", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.MYA_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ message: "Hi! What should I focus on today?" }),
});
const { reply, conversation_id } = await res.json();
console.log(reply);
import os, requests

r = requests.post(
    "{{API}}/assistant/messages",
    headers={"Authorization": f"Bearer {os.environ['MYA_KEY']}"},
    json={"message": "Hi! What should I focus on today?"},
)
print(r.json()["reply"])

The reply comes from the same assistant you talk to in My Assistant — it knows your name, your reminders and what you discussed this morning.

Keys & scopes

A key belongs to one connected app and acts as you, within the scopes you allowed that app. Send it as a bearer token (or as X-Api-Key). Keys look like mya_ followed by 40 characters.

Change an app's scopes any time in Your own apps; it takes effect on the next request. Pausing the app, revoking a key or removing the app stops it at once.

ScopeAllowsDefault
assistantTalk to your assistant (/assistant/messages).on
voiceRealtime voice sessions, and the assistant tools those sessions use.on
dataThe app's own records and activity feed.on
memory:readRead what your assistant remembers about you.on
memory:writeAdd to your memory — including facts learnt from what you say in the app.off
toolsRun any of the assistant's app-safe tools directly.off
notifySend a notification to your phone.on
profileRead your name and your assistant's name.on
Keep keys secret. A key can talk to your assistant as you. Put it on your server or in a private app, never in a public web page or a public repository. If one leaks, revoke it in Your own apps.

Talk to your assistant

POST/v1/assistant/messagesscope: assistant

Sends one message and returns the assistant's reply. Pass the returned conversation_id on the next message to continue the same thread (threads are kept 7 days).

FieldTypeDescription
messagestringWhat the user said or typed. Up to 4,000 characters.
conversation_idstringContinue an earlier thread.
toolsarrayApp tools for this conversation — see app powers. Remembered for the thread; send again to change them.
contextstring | objectWhat your app shows right now (a board, a score, the open screen). Treated as data, never as instructions. Up to 12,000 characters.
instructionsstringHow the assistant should behave in this conversation ("You are the opponent; play at club level").
include_assistant_toolsbooleanDefault true: it may also use its own tools (reminders, search, weather, lists…). Set false to keep it to your app's tools.

Response:

{
  "conversation_id": "conv_6f1c…",
  "status": "completed",          // or "requires_action"
  "reply": "Morning! You have the dentist at 4…",
  "tool_calls": [],                  // app tools to run, when requires_action
  "actions": [                        // assistant tools it ran this turn
    { "tool": "list_reminders", "ok": true, "result": "Dentist at 4 pm" }
  ]
}

Everything said here is filed in your conversation memory, marked as coming from your app — ask My Assistant "what did we talk about in my chess app?" and it can answer.

DELETE/v1/assistant/conversations/:idscope: assistant

Forgets a thread (the conversation memory it already wrote stays).

Give it app powers

Your app can do things My Assistant can't — make a chess move, start a workout, change a light's colour. Describe those actions as tools (a name, a description and JSON Schema parameters). The assistant decides when to use them; your app performs them and sends back the result.

1Send message + tools.
2Get status: "requires_action" with tool_calls.
3Do them in your app, post tool_results.
4Get the final reply (or more calls).
POST {{API}}/assistant/messages
{
  "message": "Your move!",
  "instructions": "You are playing chess against the user, as black.",
  "context": { "fen": "rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq - 0 1" },
  "tools": [{
    "name": "make_move",
    "description": "Play your move on the board, in UCI notation (e7e5).",
    "parameters": {
      "type": "object",
      "properties": { "move": { "type": "string" } },
      "required": ["move"]
    }
  }]
}
{
  "conversation_id": "conv_6f1c…",
  "status": "requires_action",
  "reply": "Classic. I'll answer in kind.",
  "tool_calls": [
    { "id": "call_9a2e…", "name": "make_move", "arguments": { "move": "e7e5" } }
  ],
  "actions": []
}
POST {{API}}/assistant/messages
{
  "conversation_id": "conv_6f1c…",
  "tool_results": [
    { "call_id": "call_9a2e…", "output": { "ok": true, "fen": "rnbqkbnr/pppp1ppp/8/4p3/4P3/8/PPPP1PPP/RNBQKBNR w KQkq - 0 2" } }
  ]
}
// a failed action: { "call_id": "…", "error": "illegal move" }
  • Answer every call in tool_calls in one tool_results request. output may be a string or any JSON.
  • Up to 24 app tools. Names: a letter, then letters, digits, _ or - (64 max), and not the name of one of the assistant's own tools.
  • The assistant never claims an app action is done before your result says so.
  • Sending a new message while calls are pending abandons them (they're recorded as not done).
Chess is only an example. App tools are any action your app can take: start a timer, add a card to a board, move a robot, open a door you own.

Voice to voice

POST/v1/voice/sessionsscope: voice

Opens a realtime voice session with your assistant — her voice, manner, memory and recent conversation — and returns a short-lived client_secret. Your app connects straight to the realtime endpoint with it; your API key never reaches the device. Accepts the same tools, context, instructions and include_assistant_tools as messages, plus an optional voice.

{
  "client_secret": "ek_…",
  "expires_at": 1760440000,
  "model": "gpt-realtime",
  "connect": { "webrtc": "https://api.openai.com/v1/realtime/calls", "websocket": "wss://…" },
  "assistant": { "name": "Hari" },
  "assistant_tools": ["web_search", "create_reminder", …],
  "app_tools": ["make_move"]
}

Connect from a browser (WebRTC)

// 1. Your server: get a session (never ship the API key to the browser)
const s = await fetch("/my-server/voice-session").then(r => r.json());

// 2. The browser: microphone in, her voice out
const pc = new RTCPeerConnection();
const audio = new Audio(); audio.autoplay = true;
pc.ontrack = (e) => (audio.srcObject = e.streams[0]);
const mic = await navigator.mediaDevices.getUserMedia({ audio: true });
pc.addTrack(mic.getTracks()[0]);
const events = pc.createDataChannel("oai-events");

const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
const answer = await fetch(s.connect.webrtc, {
  method: "POST",
  body: offer.sdp,
  headers: { Authorization: `Bearer ${s.client_secret}`, "Content-Type": "application/sdp" },
});
await pc.setRemoteDescription({ type: "answer", sdp: await answer.text() });

// 3. Tool calls arrive on the data channel
events.onmessage = async (m) => {
  const ev = JSON.parse(m.data);
  if (ev.type !== "response.function_call_arguments.done") return;
  const args = JSON.parse(ev.arguments || "{}");
  const output = s.app_tools.includes(ev.name)
    ? await runMyAppTool(ev.name, args)                    // your app's power
    : await fetch("/my-server/assistant-tool", {            // relays to POST /v1/tools/call
        method: "POST", body: JSON.stringify({ name: ev.name, arguments: args }),
      }).then(r => r.json());
  events.send(JSON.stringify({ type: "conversation.item.create",
    item: { type: "function_call_output", call_id: ev.call_id, output: JSON.stringify(output) } }));
  events.send(JSON.stringify({ type: "response.create" }));
};

Assistant tools

GET/v1/toolsscope: tools or voice

Lists the assistant's tools this key may run, with their JSON Schemas. With voice only, that's the tools its voice sessions are given; with tools, every tool that works without your phone in hand. Tools that need your explicit yes (calls, payments, messages to other people) are not available through the API.

POST/v1/tools/callscope: tools or voice
{ "name": "create_reminder",
  "arguments": { "text": "Rematch with Ravi", "due_at": "2026-10-15T19:00:00+05:30" },
  "user_text": "remind me tomorrow at 7 to have a rematch with Ravi" }

→ { "ok": true, "result": "Reminder set for tomorrow at 7 pm." }

user_text is what the user just said; tools that write to memory check against it.

Memory

GET/v1/memory?q=chess&limit=20scope: memory:read
{ "memories": [ { "id": 812, "fact": "Plays chess on weekends with Ravi", "kind": "semantic", "createdAt": 1760400000000 } ] }
POST/v1/memoryscope: memory:write
{ "fact": "Prefers playing chess as black" }

Facts added by an app are listed in your account's activity log with the app's name.

Records

Your app's own data, kept on your account: matches, scores, saved boards, settings. Organise it in collections of JSON documents (64 KB each). Give each record a short summary — it's the line My Assistant reads when you ask about it.

PUT/v1/records/:collection/:idscope: data
PUT {{API}}/records/matches/2026-10-14-ravi
{ "summary": "Beat Ravi in 34 moves with the Sicilian",
  "data": { "opponent": "Ravi", "result": "win", "moves": 34, "opening": "Sicilian" } }

→ 201 { "record": { "collection": "matches", "id": "2026-10-14-ravi", "summary": "…", "data": {…}, "createdAt": …, "updatedAt": … } }
CallDoes
POST /v1/records/:collectionCreates a record with a new id.
GET /v1/records/:collection?limit=50&before=<updatedAt>Newest first.
GET /v1/records/:collection/:idOne record.
DELETE /v1/records/:collection/:idRemoves it.
GET /v1/recordsCollections, with counts.

Activity

POST/v1/eventsscope: data

A one-line account of something that happened. It appears under the app in My Assistant's Your own apps, and it's what the assistant answers from when you ask "how did my chess match go?".

{ "type": "match_finished",
  "summary": "Lost to the assistant in 41 moves — blundered the queen on move 28",
  "data": { "result": "loss", "moves": 41 } }
GET/v1/events?limit=30&before=<id>scope: data

Notifications

POST/v1/notifyscope: notify
{ "title": "Your move", "body": "The assistant played Nf6. Your turn!" }
→ { "ok": true, "delivered": true }

Up to 20 a day per app. Each one is also kept in the app's activity.

Errors

Every error has the same shape: { "error": { "code": "…", "message": "…" } }. The message is written to be shown to a person.

StatusCodesMeaning
400message_required, bad_tools, bad_record, missing_results…The request needs fixing; the message says how.
401missing_key, invalid_keyNo key, or a revoked one.
403missing_scope, app_pausedAllow the scope, or resume the app, in Your own apps.
404unknown_conversation, not_found, unknown_toolNothing by that id for this app.
409nothing_pendingTool results sent to a conversation that isn't waiting for any.
429rate_limited, daily_limitSlow down, or wait until tomorrow (UTC).
5xxbusy, voice_unavailable, server_errorTry again shortly.

Full example: a game against your assistant

A minimal Node server for any turn-based game. Swap applyMove for your own rules.

import express from "express";
const API = "{{API}}";
const KEY = process.env.MYA_KEY;
const mya = (path, body) => fetch(API + path, {
  method: body ? "POST" : "GET",
  headers: { Authorization: `Bearer ${KEY}`, "Content-Type": "application/json" },
  body: body && JSON.stringify(body),
}).then((r) => r.json());

const TOOLS = [{
  name: "make_move",
  description: "Play your move in the current game.",
  parameters: { type: "object", properties: { move: { type: "string" } }, required: ["move"] },
}];

let game = newGame(), conversation = null;

async function talk(message) {
  let r = await mya("/assistant/messages", {
    message, conversation_id: conversation, tools: TOOLS,
    instructions: "You are the user's opponent. Be a good sport.",
    context: { board: game.board, turn: game.turn },
  });
  while (r.status === "requires_action") {
    const tool_results = r.tool_calls.map((c) => {
      const res = applyMove(game, c.arguments.move);          // your game logic
      return res.ok ? { call_id: c.id, output: { board: game.board } }
                    : { call_id: c.id, error: res.reason };
    });
    r = await mya("/assistant/messages", { conversation_id: r.conversation_id, tool_results });
  }
  conversation = r.conversation_id;
  if (game.over) {
    await mya("/events", { type: "game_over", summary: game.summaryLine, data: game.result });
    await mya("/records/games", { summary: game.summaryLine, data: game.record });
  }
  return r.reply;
}

const app = express().use(express.json());
app.post("/play", async (req, res) => {
  applyMove(game, req.body.move);
  res.json({ reply: await talk(`I played ${req.body.move}`), board: game.board });
});
app.listen(3000);

Later, in My Assistant: "How did my last game go?" → "You lost in 41 moves — the queen blunder on move 28. Rematch?"

Security & privacy

  • Only a hash of each key is stored; the key is shown once when it's made.
  • An app sees only what its scopes allow, and only its own records and activity.
  • Context and tool results from your app are treated as data, never as instructions to the assistant.
  • Calls, payments and messages to other people always need your yes in My Assistant — the API cannot do them.
  • Removing an app deletes its keys, records, activity and threads. Deleting your account deletes everything.
